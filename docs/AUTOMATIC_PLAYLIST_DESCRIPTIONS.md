# Automatic playlist descriptions

**Project:** Spotify Helper & Information Tracker (SHIT)

## Goal

Playlists without a user-authored description should have a short description that reflects their current contents, and the description should be refreshed when the playlist's identity changes. Descriptions should summarize the playlist, not advertise generic playlist filler.

## Current implementation

- Generator: `scripts/spotify/spotify_playlist_descriptions.py`
- Compatibility command: `python compat/spotify_playlist_descriptions.py PLAYLIST_ID`
- Explicit apply: `python compat/spotify_playlist_descriptions.py PLAYLIST_ID --apply`
- Regression tests: `tests/test_spotify_playlist_descriptions.py`
- Generated-description ownership state: `assistant_data/spotify/playlist_descriptions.json`

The generator reuses `playlist_intelligence.build_playlist_profile` and the existing Library-backed artist and track evidence. It can include:
- track-level mood tags where available, otherwise broader mood inference;
- genres and sound families;
- lyric-derived themes where available, otherwise profile themes;
- a neutral fallback when the evidence is too sparse.

Descriptions are deterministic, concise and capped at Spotify's 300-character limit. They are based on the playlist's own current tracklist, not the user's overall taste.

## Manual-description protection

- A non-empty description not previously recorded as generated by SHIT is treated as user-authored and is never overwritten.
- Blank descriptions are eligible.
- A description previously generated by SHIT can be refreshed as playlist content or supporting metadata changes.
- Generated descriptions are recorded with a content/profile signature and timestamp.
- The generator does not silently claim ownership of an existing non-empty description.

## Permission and rollout safeguards

The command defaults to preview-only. Applying requires both:
1. the playlist is registered as SHIT-managed or an explicitly approved exception; and
2. the playlist is explicitly unlocked, plus the caller supplies `--apply`.

This intentionally means personal playlists with blank descriptions are discoverable/previewable but remain read-only unless explicitly approved. Registering a playlist in the reference-role registry is not edit permission. Tricky Daily is an explicit exception: its dedicated midnight cycle owns a separate short editorial description rotation, documented in `docs/TRICKY_DAILY_CYCLE.md`. This generic metadata generator does not overwrite or claim ownership of that editorial description.

## Automation status / next integration

The generic metadata generator and safeguards exist, but periodic automatic invocation for general managed playlists is not yet wired into the playlist cloud workflow. Tricky Daily's separate editorial description rotation is already integrated into its midnight cycle; it is not a generic metadata refresh. The next integration step for other eligible managed playlists is a preview/confirmation command in the cloud control workflow, followed by a bounded scheduled refresh. That scheduler must:
- refresh only eligible SHIT-managed playlists (and explicit exceptions whose permissions include `details`);
- skip manual descriptions;
- compare signatures and make no API write when unchanged;
- avoid an account-wide playlist scan per playlist; reuse a single catalog pass/snapshot where practical;
- respect Spotify cooldown/429 state and never retry blindly;
- audit generated description updates and preserve the last successful description state.

Do not bulk-edit existing Spotify descriptions during rollout. First inspect preview output across a representative sample, including sparse-metadata and highly themed playlists.
